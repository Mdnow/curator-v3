# GOALS-слой «проявленные цели» — спецификация

Статус: **реализовано** (бэкенд + фронт, проверено 07.08.2026; API не прогонялось живьём, тестов на goals нет). Решение пользователя от 07.08.2026
(`TECHNICAL_JOURNAL.md` §11.7): раздел «Задачи» давит (дефицит-мышление),
вместо него — слой **«проявленные цели»**: куратор как когнитивное зеркало
выводит цели из суммарных заметок. Без чекбоксов, дат и статусов.

**Обновление 10.08.2026 (ADR-0007, ADR-0008):** вкладка «Цели» — модель
**«Созвездие»**: зеркало всегда показывает 3-5 живых направлений (текущий
фокус внимания), остальные уходят в «прошлые направления» (архив) и могут
вернуться. Дедупликация — слиянием, дубли не накапливаются.

Референс: Mem AI — Discovery Engine, Heads Up, Actionable Chat.
Вход всегда один — заметки. Цели — **выход куратора, не долг**.

---

## 0. Философия слоя

Цель в этом слое — не «дедлайн», а **обнаруженный вектор**. Куратор смотрит
на заметки за период и видит: куда ты устойчиво движешься, что возвращается,
о чём ты пишешь снова и снова. Он показывает это как зеркало:

> «За последние 30 дней ты 7 раз вернулась к теме X. Вот 3 цитаты.»

Это отличается от задачи тем, что:
- цель **нельзя провалить** — она уже проявлена в заметках;
- у цели **нет даты** — она существует, пока существует вектор;
- цель **не требует действий** — она требует узнавания.

**Созвездие (3-5).** В любой момент человек живёт не 20 направлениями,
а 3-5. Вкладка показывает **текущий фокус внимания**, а не архив: генерация
пересобирает созвездие из свежих паттернов, невыбранные направления уходят
в «прошлые» (не удаляются, сворачиваются), при возвращении вектора — цель
всплывает снова. Дубли — симптом накопительной модели; в «Созвездии» близкие
темы обязаны слиться, чтобы влезть в лимит.

## 1. Что уже есть (фундамент, не переделываем)

- `notes`: `ai_summary`, `ai_category`, `ai_sentiment`, `ai_keyphrases`, `thread_id`, `mood`, `is_favorited`
- чат-куратор с сессиями и контекстом последних заметок
- паттерны за 7/14/30 дней (`/api/insights/daily`)
- избранное как фокус-маркер

Ничего из этого не меняется. Goals-слой — **надстройка над notes**.

## 2. Модель данных

```sql
CREATE TABLE goals (
    id              SERIAL PRIMARY KEY,
    user_id         INT NOT NULL REFERENCES users(id),
    title           TEXT NOT NULL,              -- 2–4 слова
    description     TEXT NOT NULL DEFAULT '',   -- одно предложение
    evidence        JSONB NOT NULL DEFAULT '[]',-- [{note_id, quote, note_date}]
    thread_ids      JSONB NOT NULL DEFAULT '[]',-- связанные thread_id
    categories      JSONB NOT NULL DEFAULT '[]',-- связанные ai_category
    source_count    INT NOT NULL DEFAULT 0,     -- сколько заметок легло в цель
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    status          TEXT DEFAULT 'active'  -- 'active' | 'archived'
);
```

`status = 'archived'` — «прошлое направление»: не удалено, но не в созвездии.
Закреплённые (`is_pinned=1`) цели не архивируются автоматически при пересборке.

Ключевой столбец — `evidence`: **каждая цель обязана иметь цитаты-источники**.
Цель без цитаты — не показывается (это «выдуманная» цель, зеркало не врёт).

Нет полей `status` (задача), `due_date`, `completed` — намеренно. `status`
здесь — состояние отражения (в созвездии / в прошлом), не статус выполнения.

## 3. AI-генерация (пересборка созвездия)

Новый промпт `GOALS_PROMPT` в `backend/ai.py`, формат — JSON через `call_ai_json`:

```
Ты — когнитивное зеркало. Проанализируй заметки за период и собери
ТЕКУЩИЙ ФОКУС ВНИМАНИЯ: 3-5 ПРОЯВЛЕННЫХ ЦЕЛЕЙ — устойчивых направлений,
к которым пользователь возвращается вновь и вновь.

Цель — НЕ задача и НЕ мечта. Цель = паттерн, подтверждённый цитатами.

ГЛАВНОЕ — ОДНА ТЕМА = ОДНА ЦЕЛЬ, НЕ ДУБЛИРУЙ:
- Разные формулировки одной темы («написать книгу», «работа над книгой»)
  — это ОДНА цель, собери все цитаты в её evidence.
- Название — устойчивая именная форма (тема, не случайный глагол).
- Выбирай только устойчивые направления; слабые паттерны отбрасывай.
- Упорядочь цели по силе: больше подтверждений в окне — выше.
- Если паттерн уже покрыт существующей целью (в т.ч. архивной) — верни
  её id в "existing_goal_id", не создавай новую запись.

ВЕРНИ JSON:
{
  "goals": [
    {
      "title": "2-4 слова",
      "description": "одно предложение — куда ведёт вектор",
      "evidence": [{"quote": "точная цитата из заметки", "note_id": 123}],
      "thread_ids": ["uuid"],
      "categories": ["Саморазвитие"],
      "existing_goal_id": null
    }
  ]
}

ПРАВИЛА:
- 3-5 целей, не больше пяти.
- Каждая цель обязана иметь минимум 2 цитаты из РАЗНЫХ заметок.
- Цитата — дословно из текста, не пересказ.
- Не выдумывай цели, которых нет в данных.

СУЩЕСТВУЮЩИЕ ЦЕЛИ (JSON): активные и архивные цели с полем status.
ЗАМЕТКИ: тексты за период.
```

Пересборка в коде (`_generate_in_background`):
- существующие цели (с `status`) передаются в промпт;
- цели из ответа AI: `existing_goal_id` → обновление + `status='active'`
  (архивная цель «оживает»); иначе — INSERT новой активной;
- все активные цели, не выбранные AI и не закреплённые → `status='archived'`;
- при сбое AI — ничего не трогаем (текущее созвездие сохраняется).

## 4. API

| Endpoint | Метод | Что делает |
|---|---|---|
| `/api/goals` | GET | `{active: [...], archived: [...]}` — созвездие и «прошлые направления» |
| `/api/goals/{id}` | GET | цель + полный evidence (с расшифрованными цитатами) |
| `/api/goals/generate` | POST | пересобрать созвездие из заметок (фоново) |
| `/api/goals/{id}/archive` | POST | «убрать из зеркала»: из созвездия в архив (не удаление) |
| `/api/goals/{id}/activate` | POST | вернуть цель в созвездие вручную |
| `/api/goals/{id}` | DELETE | полное удаление цели |
| `/api/goals/{id}/pin` | POST | закрепить вверху (закреплённые не архивируются при пересборке) |

Правила генерации:
- берутся заметки за период (по умолчанию 30 дней, ограничение: 100 заметок);
- генерация **фоновым таском** (паттерн `BackgroundTasks` из notes.py);
- при сбое AI (`AI_LAST_ERROR`, 429) — текущее созвездие сохраняется,
  вернуть понятное сообщение;
- генерация = **пересборка** (ADR-0008): активные = выбор AI (3-5),
  невыбранные активные (кроме закреплённых) уходят в архив.

## 5. Frontend

Раздел «Задачи» (`tasksSection` в `index.html`) скрывается из навигации
(и десктоп-сайдбара, и мобильной нижней панели). Бэкенд `/api/tasks`
**остаётся** — данные не удаляем, UI просто не ведёт на него.

Новый раздел «Цели» (`goalsSection`) с шаблоном-минимализмом:

```
┌──────────────────────────────────────┐
│ ЦЕЛИ                          [⟳]    │  ← «пересобрать созвездие»
│                                      │
│ ▸ Свобода без суррогата     ▂▂▂▂▂▂   │  ← title + пульс силы
│   Побег из СП не через разрушение    │  ← description
│   6 подтверждений · последнее 07.08  │  ← strength
│   ┌ цитата 1 … (07.08) ┐            │  ← evidence, клик открывает заметку
│   ┌ цитата 2 … (01.08) ┐            │
│   [закрепить]  [в архив]            │
│ ─────────────────────────────────────│
│ [прошлые направления · 3 ▾]         │  ← архив, раскрывается по клику
└──────────────────────────────────────┘
```

Особенности UI:
- **созвездие**: всегда 3-5 активных карточек; у каждой — пульс силы
  (полоска = число подтверждений относительно сильнейшей + «N подтверждений ·
  последнее дата»);
- **прошлые направления** — раскрывающийся блок с архивными целями
  (приглушённые), кнопка «вернуть» возвращает цель в созвездие;
- кнопка «обновить цели» вызывает `/api/goals/generate`;
- пустое состояние: «заметок пока мало, чтобы зеркало что-то увидело» —
  не «у тебя нет целей» (это важно: отсутствие вывода ≠ отсутствие целей);
- эмодзи не используются (правило §6.2 журнала).

## 6. Вариант Б — «цель-диалог» (пост-шаг, не в первой итерации)

Кнопка «поговорить о цели» открывает чат с куратором, где в контекст
добавляется выбранная цель + её evidence + последние заметки по thread_ids.
Куратор задаёт один вопрос и помогает углублять вектор.
Реализуется уже существующим `/api/ai/chat` с дополнительным контекстом —
отдельного эндпоинта не нужно.

## 7. Проверка (как убедиться, что работает)

1. Локально: создать 5–7 тестовых заметок по одной теме → `generate` →
   цель появилась, у неё ≥2 цитат из разных заметок, цитаты дословные.
2. Проверка счёта: `source_count` = число заметок в evidence.
3. Сбой-тест: отключить `OPENROUTER_API_KEY` → `generate` возвращает
   понятную ошибку, старые цели не затираются.
4. Фронт: раздел «Задачи» исчез из навигации, «Цели» появился;
   десктоп + мобайл; клик по цитате ведёт в нужный день.
5. Прогон по реальным данным (user `mdnow`) на проде.

## 8. Долги / ограничения

- Генерация целей — AI-вызов (OpenCode Zen + OpenRouter fallback).
  Не чаще 1 раза в день, лучше вручную по кнопке.
- `evidence` хранит копии цитат — при редактировании заметки цитата не
  обновляется автоматически. Пересборка заменяет evidence свежим окном.
- Дедупликация и удержание лимита 3-5 — на совести AI (ADR-0007/0008):
  модель указывает цель через `existing_goal_id`, код лишь валидирует id
  и архивирует невыбранных. Если AI вернёт <3 целей — созвездие неполное
  (приёмлемо при слабых данных), >5 — код не ограничивает.
- Существующие цели передаются в промпт с обрезкой до 8000 символов —
  при очень большом архиве старые цели могут не попасть в контекст.
