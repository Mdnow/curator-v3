# Журнал технических проблем — Curator v3

Период: июль — август 2026. Автор: AI-ассистент (opencode).
Стек: FastAPI + PostgreSQL (Neon) + vanilla JS. Деплой: Railway.
AI-провайдер: OpenRouter, free-модели.

---

## 1. AI / OpenRouter

### 1.1. Free-модели постоянно возвращают 429 (главная боль)

**Проблема.** Категории заметок не заполнялись, чат отвечал «AI временно недоступен. Попробуй через минуту».

**Причина (две, и обе были важны):**

1. **Невалидный `OPENROUTER_API_KEY` на Railway.** Строка ключа в Railway-окружении была устаревшей (72 симв., `401 User not found` при прямом запросе к OpenRouter). Локальный ключ в `.env` (73 симв.) работал. Из-за этого прод **вообще не мог ходить в AI** — упали и категории, и чат. Диагностика: вытащили ключ Railway через `railway variables --json`, сравнили с локальным, прогнали напрямую против OpenRouter — все три тестовые модели вернули 401.

2. **Узкая ротация моделей.** В v3 было только 3 free-модели, из которых `google/gemma-4-31b-it:free` стабильно в 429. v2 решал это широкой ротацией из 7 моделей — v3 её случайно зарезали.

**Решение.**

- Обновили ключ: `railway variables --set "OPENROUTER_API_KEY=$key"` (значение из локального `.env`) + редеплой.
- Расширили `FREE_MODELS` до 6 моделей, проверенных вживую:
  - `nvidia/nemotron-3-super-120b-a12b:free` — работает
  - `google/gemma-4-26b-a4b-it:free` — работает
  - `nvidia/nemotron-3-ultra-550b-a55b:free` — работает
  - `nvidia/nemotron-3-nano-30b-a3b:free` — работает
  - `google/gemma-4-31b-it:free` — в 429, оставлен как fallback
  - `openai/gpt-oss-20b:free` — возвращает 200 с пустым `content` (учтено guard-ом)
- Убрали мёртвые: `poolside/laguna-m.1:free` → **404 No endpoints found**, `openrouter/free` → 200 с пустым `content`.
- Сделали **двойной проход** по списку (2 раунда по всем моделям) — на случай кратковременных 429.
- Добавили **guard на пустой контент**: раньше `content=None` возвращался как успех, из-за чего чат мог получить `None` и упасть в `re.search`.

**Ключевой вывод.** Прежде чем винить модели — проверь ключ. Один невалидный ключ на проде отключает весь AI-функционал, а ошибка выглядит как «free-модели отвалились».

### 1.2. Модель возвращает обрезанный JSON → fallback «без категории»

**Проблема.** `analyze_note` иногда возвращал пустую категорию, хотя `call_ai` отвечал успешно. Сырой ответ обрывался на середине JSON: `{"summary": "...", "category": "Наблюдения", "sentiment` — без закрывающих скобок. `json.loads` падал, и функция отдавала fallback.

**Причина.** У free-моделей качество генерации нестабильно: некоторые завершают ответ раньше конца JSON. Плюс старая логика `call_ai` возвращала **первый** ответ с HTTP 200, даже если JSON был битый — хорошие модели не получали шанса.

**Решение.** Ввёл `call_ai_json()` — парсит ответ каждой модели и пробует следующую, пока не получит валидный JSON:
- `_request_model(client, model, ...)` — единый вызов с обработкой 429/ошибок/пустого контента.
- `_parse_json_content()` — срезает markdown-обёртки ``` ``` ````, парсит JSON, принимает только `dict`.
- `call_ai_json()` — 2 прохода по всем моделям, возвращает первый валидный JSON.
- `analyze_note`, `analyze_dream`, `daily_patterns`, `thread_suggest` переведены на `call_ai_json`.

**Результат.** Локально и на проде категория стабильно определяется («Саморазвитие», «Задачи» и т.п.), summary/sentiment/keyphrases заполняются.

### 1.3. Двойное экранирование `{{ }}` в промптах

**Проблема.** `DAILY_PATTERNS_PROMPT` и `THREAD_SUGGEST_PROMPT` содержат JSON в теле промпта и вызываются через `.format()`. Фигурные скобки `{` в JSON уходили в `.format()` как шаблон → `KeyError` / мусор.

**Решение.** Экранировать: `{{ }}` вместо `{ }` в местах, где вызывается `.format()`.

### 1.4. Таймауты

**Проблема.** При полном отказе всех моделей запрос мог висеть до 3 минут (6 моделей × 15с × 2 прохода), и фронт уходил в «ошибка соединения».

**Решение.** Пока принято как есть: рабочие модели отвечают быстро, 429 приходят мгновенно. Таймаут `httpx.AsyncClient(timeout=15)` на один вызов. Дальнейшее усиление — через freellmpool (см. §1.6).

### 1.5. Урок по ротации free-моделей

- Каталог free-моделей OpenRouter меняется: модель может исчезнуть (404) или уйти в перманентный 429.
- Перед фиксацией списка — тестировать каждую модель отдельно, коротким таймаутом (одна «зависающая» модель блокировала весь пакетный тест).
- Ротация должна быть **широкой и парсить JSON**, а не просто брать первый 200.
- Список актуальных free-моделей можно получить: `GET /api/v1/models` с заголовком `Authorization: Bearer $key`, фильтр `id like "*:free"`. На момент теста — 14 моделей.

### 1.6. Планы: freellmpool (не внедрено)

**Проблема.** Одиночный пул free-моделей OpenRouter всё равно хрупкий (429, суточные лимиты).

**Идея.** `0xzr/freellmpool` — пул free-тиров 24 провайдеров (Groq, Cerebras, Gemini, NVIDIA, OpenRouter, keyless-провайдеры Pollinations/OVHcloud/Kilo и др.) за одним OpenAI-совместимым endpoint с авто-failover и квотой на день. Даёт resilience там, где текущая ротация одного провайдера упирается в лимит.

**Статус (решение от 06.08.2026).** Зафиксировано как рекомендация, **внедрять не стали**: корневая причина 429 устранена валидным ключом + ротацией из 6 free-моделей, рабочее поведение подтверждено на проде. Если снова упрёмся в лимиты — первым шагом расширить `FREE_MODELS` из каталога `/api/v1/models`, вторым — внедрить `0xzr/freellmpool` (Python-библиотекой внутрь backend, либо отдельным Railway-сервисом-proxy).

## 2. Кодировки / кракозябры

### 2.1. Кракозябры в тестах (НЕ баг приложения)

**Проблема.** Ответы API выглядели как `�۶� �������㯥�` или `РљСѓСЂР°С‚РѕСЂ`, хотя сайт работал.

**Причина.** Это была **консоль/инструменты**, не приложение:
- PowerShell 5.1 и окно bash-тула неправильно декодируют UTF-8 в кириллице.
- Сырые байты были валидным UTF-8 (проверено hex: `D0 B2 D1 80...` = «вре...»).

**Решение (рабочий паттерн для проверок):**
- Не смотреть на ответ в консоли. Писать через `curl.exe -o file.json` (сырые байты) и читать файл инструментом `Read` или скриптом Python с записью в файл.
- **Никогда** `Out-File -Encoding ascii` для кириллицы — заменяет все не-ASCII на `?` и портит данные (дважды наступали на это при диагностике).
- `Out-File -Encoding utf8` в PS 5.1 пишет UTF-8 **с BOM** — если тело JSON уходит в запрос, BOM попадает в строку (портит префикс сообщения).
- Для POST-тела JSON: писать файл и слать `curl.exe --data-binary @file`, а не экранировать JSON в кавычках (в PS 5.1 экранирование ломается).

### 2.2. Приложение само по себе с кодировкой в порядке

- FastAPI отдаёт UTF-8 корректно; сырые байты ответа валидны.
- Фронт экранирует через `esc()` и innerHTML-безопасно; в базе текст хранится в UTF-8.
- Favicon отсутствует → 404 в консоли браузера, на работу не влияет.

## 3. Railway-деплой

### 3.1. Пуш в GitHub НЕ деплоит на Railway

**Проблема.** Казалось, что после `git push` всё само задеплоится. Оказалось — последний успешный деплой был недельной давности, все мои фиксы не доезжали.

**Причина.** Сервис не привязан к GitHub-источнику (собирается из загруженного кода, не из репозитория).

**Решение.** Деплой вручную через Railway CLI:
```
railway up --detach        # собрать из локальной папки и задеплоить
railway redeploy --yes     # пересобрать текущий деплой
railway deployment list    # статус (SUCCESS / DEPLOYING / FAILED / REMOVED)
```
Для диагностики деплоя `railway deployment logs` НЕ существует — используется `railway logs` (рантайм-логи контейнера).

### 3.2. Окружение Railway

- Токен CLI лежит в `~/.railway/config.json` (`accessToken`) — Railway CLI доступен без доп. настройки.
- Переменные: `railway variables` (таблицей), `railway variables --json` (машинно-читаемо), `railway variables --set "K=V"`.
- `--set` переменной может триггерить автодеплой; иногда создаёт два деплоя подряд. Перепроверять `deployment list`.
- **Секреты НЕ должны попадать в репозиторий**: `.env` в `.gitignore`. Для загрузки на Railway добавили `.railwayignore` (исключает `.env`, скриншоты, тест-файлы), т.к. `Dockerfile` делает `COPY . .`.

### 3.3. Несколько деплоев подряд

**Проблема.** Ручной деплой + автодеплой от смены переменной дали параллельные деплои, один ушёл в FAILED.

**Решение.** Не страшно: Railway держит последний SUCCESS как активный. Ориентироваться на `deployment list`, ждать статуса именно нужного ID.

## 4. Фоновые задачи и БД

### 4.1. AI-вызовы внутри блокировки пула БД

**Проблема.** `_analyze_in_background` (notes), `_analyze_dream_in_background`/`dream_insight_endpoint`/`dream_patterns` (dreams), `daily_insight` (insights) делали AI-запросы (до 45-180с!) **внутри** `pool.acquire()` / `get_db()` — держали соединение с БД, пока AI думает. Это исчерпывало пул и вешало сервис.

**Решение.** Вынести все AI-вызовы из контекста соединения: сначала `await analyze_*(...)`, затем отдельно `await pool.acquire()` для записи результата.

### 4.2. Единый паттерн доступа

- Чтение: `async with get_db() as db:` (выдаёт соединение из пула).
- Фоновые задачи: брать пул через `from backend.db import get_pool`, `pool.acquire()`, закрывать после записи.
- Никогда не держать соединение во время сетевых вызовов к OpenRouter.

## 5. Чат и сессии (задача «архив — бардак»)

### 5.1. История «перемешана» между диалогами

**Проблема.** Сессии были временны́ми корзинами (новая через 2ч после последнего сообщения), но контекст для AI брался из **последних 40 сообщений всех времён** — диалоги смешивались. Архив был отдельной read-only панелью без возможности продолжить диалог.

**Решение.**
- Backend: `POST /ai/chat` принимает опциональный `session_id`. Если передан и принадлежит пользователю — продолжаем эту сессию; история для контекста фильтруется по сессии.
- Новый диалог: фронт шлёт `session_id: null`, backend решает (новая при разрыве >2ч, иначе продолжение последней).
- `DELETE /chat/sessions/{id}` — удаление диалога; `/chat/history` — очистка всех.
- Frontend: топбар чата «куратор» + кнопки `✚` (новый диалог) и `☰` (диалоги). Список диалогов: дата, превью (первое сообщение = название), счётчик сообщений, кнопка удаления `✕`, поиск, «очистить всё». Клик по диалогу — закрывает панель и **загружает переписку прямо в окно чата**, `currentSessionId` запоминается, отправка продолжает этот диалог.

### 5.2. Куратор не видел паттерны

**Проблема.** Контекст чата = последние 30 заметок + избранное. Пользователь просил: куратор должен видеть связи и паттерны мыслей.

**Решение.** В system-промпт добавлены без AI-вызова (правильно дёшево):
- `СВОДКА ТЕМ` — подсчёт AI-категорий за последние заметки (без «без категории»), топ-4.
- `ПОСЛЕДНИЕ ЗАПИСИ О СНАХ` — последние 5 расшифрованных снов.
- Избранные мысли как фокус (было).
Проверено на проде: куратор ответил со ссылкой на «свободу и дышащую среду» из реальных заметок.

## 6. Frontend

### 6.1. Кэш браузера душит новые версии

**Проблема.** CSS/JS меняются, браузер кэширует старые файлы.

**Решение.** Cache-busting query: `?v=4` → `?v=5` во всех `<link>`/`<script>` в `index.html` при каждом выпуске фронтенда.

### 6.2. Эмодзи в UI

**Правило пользователя:** никаких эмодзи. Заменены на текст/геометрические глифы: `≡`, `✎`, `☐`, `☽`, `◇`, `✦`, `↓`, `•`, `mic`. При новом коде проверять, что не затесался эмодзи (находили `📕` в кнопке архива → заменён на `☰`).

### 6.3. `isMobile()` была константой

**Проблема.** `isMobile()` был константой, вычисленной один раз — ресайз не пересчитывал мобильный режим.

**Решение.** Сделать `isMobile()` функцией (проверка ширины на каждый вызов).

### 6.4. Мобильный чат

- Чат на мобильном полноэкранный: скрыт header и bottom bar, добавлена кнопка «назад» (`←`).
- Панель диалогов — внутри чат-секции, работает и на десктопе, и на мобильном.

## 7. PowerShell / инструменты (окружение Windows)

Набор граблей, на которые наступали в этой сессии:

1. **`&&` не работает** в PowerShell 5.1 — цепочки команд через `;` + `if ($?)`.
2. **`git push`** пишет в stderr → PowerShell оборачивает в `NativeCommandError` — это не ошибка, смотреть последнюю строку (`master -> master`).
3. **`Out-File`** — кодировки см. §2.1 (ascii убивает кириллицу, utf8 добавляет BOM).
4. **Python `-c "..."`** с русским текстом и `\n` в кавычках ломается парсером PowerShell — выносить логику в `.py`-файл.
5. **curl.exe** с `-d '{"..."}'` в PS 5.1 — экранирование кавычек ломается. Правильно: файл + `--data-binary @file`.
6. **Вывод кириллицы в консоль** — всегда через файл + `Read`, не в stdout.
7. **LSP-предупреждения**: `Import "backend.config" could not be resolved` — ложная тревога (модуль резолвится при запуске как пакет).

## 8. Не решено / известные ограничения

- **Оператор блокирует Railway CDN-адреса** (69.46.46.124) без VPN — то же самое было с v2. Рабочее решение для Марины — VPN на телефоне; сам сервис жив.
- **Реанализ старых заметок «без категории»**: у заметок, созданных в сломанный период, `ai_category='без категории'` навсегда (нет reanalyze-эндпоинта). Планируется endpoint + кнопка переанализа.
- **Backup не включает AI-поля** (ai_summary, ai_category, ai_sentiment, ai_keyphrases, thread_id, mood) — при восстановлении AI-разметка теряется. Открытый долг.
- **freellmpool** — кандидат на пул провайдеров, не внедрён (§1.6).
