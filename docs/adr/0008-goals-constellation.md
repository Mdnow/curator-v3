# ADR-0008 — «Цели» = созвездие: 3-5 живых направлений

- **Дата:** 10.08.2026
- **Статус:** accepted

## Контекст

Вкладка «Цели» копила паттерны: каждая генерация добавляла, ничего не
уходило. Через месяц — десятки целей, зеркало переставало быть зеркалом.
Пользователь: «мне любопытно наблюдать за 3-5 сформировавшимися группами —
не более». Дубли — симптом накопительной модели, не отдельный баг.

## Решение

Модель **«Созвездие»**: вкладка показывает текущий фокус внимания (3-5
живых направлений), а не архив. Генерация = **пересборка**, не дополнение:

- Промпт: 3-5 целей, одна тема = одна цель (группировка дублей), цель —
  устойчивая именная форма; существующие цели (с `status`) передаются
  в промпт, дубль помечается `existing_goal_id` (архивная цель «оживает»).
- Код: цели из ответа AI → активные (обновление/INSERT), все активные,
  не выбранные AI и не закреплённые → `status='archived'`.
- Архив («прошлые направления») не удаляется: вектор вернулся — цель
  всплывает снова.
- Сила цели = `source_count` (подтверждения в окне) + `last_activity`;
  UI показывает пульс (полоска + «N подтверждений · последнее дата»).
- Ручные действия: «в архив» / «вернуть» (не «удалить»); DELETE остаётся
  для полного удаления; закреплённые не архивируются при пересборке.

## Альтернативы

- Только починить дедуп — отклонено: не решает накопление и потерю фокуса.
- Скрывать всё сверх 5 на фронте без пересборки — отклонено: архив
  не связан с моделью, «прошлые» не возвращаются сами.
- Жёсткий лимит «ровно 5» в коде — отклонено: при слабых данных AI честно
  вернёт меньше; лимит — инструкция модели, не закон.

## Последствия

- Вкладка всегда чистая: 3-5 карточек + раскрывающийся архив.
- Старые дубли, уже лежащие в БД, не склеиваются автоматически — при
  пересборке невыбранные уходят в архив, пользователь может удалить.
- Новая колонка `status` (миграция в `init_db`), API `/goals` возвращает
  `{active, archived}`, добавлены `/archive` и `/activate`.
- Качество созвездия зависит от AI: если он вернул <3 целей, созвездие
  неполное (приемлемо при слабых данных).
