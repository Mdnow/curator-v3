# ADR-0012 — Сохранение из чата по явной просьбе (маркер [SAVE:...])

- **Дата:** 12.08.2026
- **Статус:** accepted

## Контекст

Пользователь: «дать функционал куратору сохранять что либо по моей просьбе».

Раньше (07.08) в чате был маркер `[AUTO_SAVE:...]`, который убрали решением
пользователя — «это опасная функция, пусть сохраняет после того как я его
прошу». После удаления куратор при явной просьбе «сохрани» только говорил
нажать кнопку сохранения — сам не сохранял. Кнопка сохранения мысли
(`/api/ai/save-thought`) была, но её блок в чате не рендерился.

Нужно вернуть сохранение из чата, но строго в рамках «только по явной просьбе».

## Решение

- `CHAT_SYSTEM`: при ЯВНОЙ просьбе пользователя («сохрани», «запиши», «запомни»,
  «это важно», «save») куратор добавляет в конец ответа блок `[SAVE:точный текст]`
  и подтверждает сохранение. Без явной просьбы маркер не добавляется никогда
  (правило из решения 07.08 сохранено).
- `chat.py` `/api/ai/chat`: после ответа AI извлекает текст из `[SAVE:...]`,
  вырезает маркер из ответа (пользователь и история чата видят чистый текст),
  сохраняет заметку «Цитаты» с AI-разметкой через общий хелпер `_save_note`
  (тот же, что использует `/api/ai/save-thought`).
- Ответ содержит `saved: {text, note_id}`; фронт под сообщением куратора
  показывает подтверждение «куратор сохранил это в заметки».
- Дополнительно: у сообщений куратора появилась кнопка «копировать»
  (копирует текст ответа в буфер обмена).

## Альтернативы

- Оставить только кнопку сохранения (без маркера) — отклонено: пользователь
  просил, чтобы куратор сам сохранял по просьбе, без лишних кликов.
- Снова автосохранять без просьбы — отклонено, прямо противоречит решению 07.08.
- Фолбэк: если AI не поставил маркер, а пользователь просил сохранить —
  сохранять сообщение пользователя. Отклонено: куратор мог сформулировать
  итог лучше, авто-фолбэк непредсказуем.

## Последствия

- Сохранение из чата работает по одному каналу с кнопкой «сохранить» —
  общий код, одна логика AI-разметки.
- Риск ложного маркера от дешёвых моделей ограничен: маркер нужен только при
  явной просьбе, а текст сохраняется из самого ответа куратора.
- История чата чистая: маркеры не попадают в `chat_history`.
