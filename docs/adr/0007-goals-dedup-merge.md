# ADR-0007 — Дедупликация целей через слияние с существующими

- **Дата:** 10.08.2026
- **Статус:** accepted

## Контекст

Генерация целей (`/api/goals/generate`) при каждом прогоне возвращала одну
и ту же тему с чуть отличающимся названием («написать книгу» vs
«работа над книгой»). Старая дедупликация — по точному совпадению
`title` (normalized lowercase) — не ловила такие дубли, и зеркало
наполнялось похожими целями.

## Решение

Дедупликация через слияние (merge):

- `generate_goals()` принимает список существующих целей
  (`[{"id", "title", "description"}]`) и передаёт его в `GOALS_PROMPT`.
- Промпт: одна тема = одна цель; название — устойчивая именная форма;
  если паттерн уже покрыт существующей целью — вернуть её id в поле
  `existing_goal_id` (не выдумывать).
- Код валидирует `existing_goal_id` по переданным id (защита от
  галлюцинаций) и вместо вставки дубля дополняет evidence существующей
  цели уникальными цитатами (по ключу note_id+quote), обновляя
  `source_count` и `updated_at`.
- Страховка в коде без AI — точное совпадение `title` (lowercase),
  работает даже если AI не заполнил `existing_goal_id`.

## Альтернативы

- Только улучшить промпт — отклонено: разные прогоны не знают друг о
  друге, без передачи существующих целей дедуп ненадёжен.
- Второй AI-проход для сравнения кандидатов с существующими — отклонено:
  удваивает AI-вызов, один проход с контекстом дешевле и проще.
- Эвристика схожести слов (Jaccard и т.п.) без AI — отклонено: на русском
  без лемматизации ненадёжна, даёт ложные срабатывания.

## Последствия

- Существующие цели больше не плодятся, при перегенерации они растут
  новыми цитатами (объединяются).
- Старые дубли, уже лежащие в БД, не удаляются автоматически — их
  чистит пользователь вручную («убрать из зеркала»).
- Стоимость промпта немного выросла (вставляется JSON существующих целей,
  обрезается до 4000 символов).
