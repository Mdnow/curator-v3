# ADR-0020: TikTok-вход — структурный анализ и AI-скиллы (паттерн ChillScript)

Дата: 15.09.2026
Статус: accepted

## Контекст

TikTok-пайплайн (ADR-0011) превращает ссылку в **перевод транскрипта + заметку**
в зеркале. Этого достаточно для когнитивного отражения («что меня ведёт»),
но недостаточно для **производства контента** («что я могу из этого сделать»).

Референс — приложение ChillScript (chillnoteai.com, «AI creator notes»):
видео → структурированная заметка (source, author, transcript, hook), поверх
которой работают переиспользуемые AI-скиллы: генерация хуков «на свой лад»,
переписывание идеи, объяснение виральности, подписи.

Пользователь (15.09.2026) выбрал перенос **всех** фич ChillScript в куратор,
**кроме голосового входа** (не нужен). Конкретно сохранено:

- карта структуры транскрипции: где **хук**, где **история**, где **результат**,
  где **ошибка**, где **парадокс**;
- несколько вариантов хука «на свой лад»;
- кнопка «переписать» (своя версия эссе на основе идеи видео);
- кнопка «почему виральное» (разбор причин клипабельности);
- подпись к картинке (пост-описание для обложки/скриншота — подчёркнуто
  пользователем как важное);
- «скилл-результат»: результат работы скилла — отдельно сохраняемая сущность.

## Решение

### 1. Расширение модели хранения (видео ≠ заметка)

Видео и заметка — разные сущности. Метаданные и структурный анализ видео
хранятся в `tiktok_tasks` (расширенные колонки), заметка в зеркале остаётся
переводом с тегом `tiktok`.

В `tiktok_tasks` добавляются колонки:

| Колонка | Тип | Что хранит |
|---|---|---|
| `description` | TEXT | описание видео из TikTok |
| `hashtags` | TEXT (JSON) | хэштеги из описания |
| `duration` | REAL | длительность, сек |
| `ai_hook` | TEXT | главный хук видео (что зацепило) |
| `ai_map` | TEXT (JSON) | карта транскрипта: `{hook|story|result|mistake|paradox}` — цитаты/отрезки |
| `ai_viral` | TEXT (JSON) | почему видео виральное: `{reasons[], mechanics[]}` |

### 2. Анализ в пайплайне

После перевода (Groq llama / Zen / OpenRouter) в `process_task` добавляется
**один** дополнительный AI-вызов `analyze_tiktok_structure(translation)`,
который возвращает JSON: `{hook, map:{hook,story,result,mistake,paradox}, viral}`.

Уже извлекаемые метаданные (`author`, `description`, `hashtags`, `duration`)
сохраняются в задачу, а не теряются (баг ADR-0011).

### 3. AI-скиллы — эндпоинт

`POST /api/tiktok/{task_id}/skill` — `{skill: <имя>, params?: {...}}`.
Результат возвращается на фронт, **не сохраняется в заметку без явной просьбы**
(паттерн «безопасный чат», ADR-0012).

Скиллы первой волны (все на существующем LLM-стеке `call_ai`/`call_ai_json`):

| Skill | Вход | Выход |
|---|---|---|
| `hooks` | перевод + `ai_hook` | 3-5 хуков «на свой лад» в стиле пользователя (Direct / Question / Contrast) |
| `rewrite` | перевод | своя версия эссе по идее видео |
| `why_viral` | перевод + `ai_viral` | человекочитаемый разбор виральности |
| `caption` | перевод + title | подпись к картинке (для поста с обложкой/скриншотом) |

Скиллы — **изолированные функции в `backend/tiktok_skills.py`**, каждый
со своим промптом (SKILLS_PROMPTS в `backend/ai.py`). Базовый текст берётся из
горячей заметки задачи (`note_id`), т.к. это перевод, а не сырой транскрипт.

### 4. Скилл-результат (сохранение)

По просьбе пользователя («сохрани результат») фронт вызывает
`POST /api/notes` (существующий маршрут) с тегом `tiktok-skill` —
общая механика, отдельная сущность не заводится. В карточке результата
кнопка «сохранить в зеркало».

### 5. Frontend

Карточка задачи TikTok расширяется:

- блок «карта транскрипции» (хук / история / результат / ошибка / парадокс) —
  раскрывающийся, цитаты кликабельны в полный текст;
- блок «хук» с кнопкой **варианты на свой лад**;
- кнопки действий над задачей: **переписать**, **почему виральное**, **подпись к картинке**;
- результат скилла — модалка с кнопками «скопировать» и «сохранить в зеркало»;
- busy-состояния и таймауты — по ADR-0015.

### 6. Ограничения

- Ключевой LLM-стек: Zen первым (`big-pickle`), OpenRouter fallback (T-011).
- Виральность и структура — субъективная интерпретация модели, не аналитика TikTok.
- Скилл «подпись к картинке» — текст подписи, а не распознавание самой картинки.

## Последствия

- **+** Зеркало получает инструмент производства: из «что меня ведёт» вырастает
  «что я могу из этого сделать» — без отдельного приложения.
- **+** Метаданные видео перестают теряться (author/desc/hashtags уже скачиваются).
- **+** Скиллы переиспользуемы и расширяемы (вторая волна — custom skills).
- **−** Дополнительный AI-вызов на каждое видео (~увеличение латентности задачи).
- **−** Структурный анализ субъективен (одна модель, без граунд-трута).
- **−** Транскрипт (сырой) не хранится — скиллы работают по переводу; для
  длинных эссе может не хватить перевода, решается ретраем с сырым транскриптом
  (стратегия fallback).

## Альтернативы (отклонены)

1. **Хранить анализ в `notes`** — заметка должна оставаться чистым отражением
   («перевод + мысль»), видео-контекст живёт в своей задаче. Отклонено.
2. **Голосовой вход** — отклонено пользователем (15.09.2026), не нужен.
3. **Отдельный сервис скиллов** — противоречит ADR-0011 (один код, одна база).
