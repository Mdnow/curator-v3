# ADR-0013 — Папки-проекты: контейнеры с диалогом и материалами

- **Дата:** 16.08.2026
- **Статус:** accepted

## Контекст

В Кураторе нет структуры для раздельной работы по темам: материалы (заметки)
и переписка с куратором размазаны по общему потоку. Задача из «Карты дня»:
дать упорядоченное рабочее пространство по делам/темам — целевой диалог и
материалы внутри изолированного проекта, как в ChatGPT/Claude.

## Решение

**Модель данных**

- Таблица `projects` (`id`, `user_id`, `name`, `created_at`, `updated_at`).
  Имя — открытый текст (как `goals.title`); шифруются только поля `*_encrypted`
  (см. ADR-0002).
- `notes.project_id` (nullable, `ON DELETE SET NULL`) — материалы проекта.
  Удаление проекта НЕ удаляет заметки, только снимает привязку.
- `chat_history.project_id` (nullable, `ON DELETE CASCADE`) — диалог проекта.
  Удаление проекта удаляет его диалог.
- `project_id = 0` в `PUT /api/notes/{id}` означает «снять привязку».

**API** (`backend/routes/projects.py`)

- `GET/POST /api/projects`, `GET/PUT/DELETE /api/projects/{id}`.
- `GET /api/projects/{id}` возвращает проект + материалы (`notes`) + диалог
  (`messages`) одним запросом.

**Диалог проекта** (`chat.py`, `/api/ai/chat`)

- В `ChatReq` добавлен `project_id`. Если он задан — диалог проекта:
  постоянный (без правила «новая сессия через 2 часа»), фильтр по
  `project_id`, `session_id` не участвует.
- Контекст куратора в проекте = материалы проекта (последние 30 заметок),
  а не общий поток.
- Сохранение по явной просьбе `[SAVE:...]` внутри проекта попадает в
  материалы проекта (`_save_note` получил `project_id`).

**Фронтенд**

- Список папок в сайдбаре (и в мобильном drawer), создание через inline-поле.
- Экран проекта: заголовок (переименование/удаление), блок материалов
  (заметки проекта + поле «новая заметка в проект»), диалог с куратором.
- Существующие заметки связываются через кнопку «в проект» в карточке →
  модалка выбора проекта (и «убрать из проекта»).

## Альтернативы

- Своя таблица `project_messages` вместо `project_id` в `chat_history` —
  отклонено: переписка живёт в одном месте, обычный чат и проекты делят
  единую историю и логику контекста.
- Отдельная таблица связей заметок (`project_notes`) — отклонено: простая
  колонка `project_id` в `notes` проще, а заметка в одном проекте — это
  текущий use-case.
- Шифровать имя проекта — отклонено: консистентно с целями (открытый текст),
  а список проектов показывается в сайдбаре и должен читаться без дешифровки.

## Последствия

- Диалоги проектов и обычные сессии не пересекаются по `session_id`.
- `chat_history` и `notes` получают nullable-колонки (миграция `init_db`
  идемпотентна, `ADD COLUMN IF NOT EXISTS`).
- Существующие заметки не теряются: `project_id` пуст у всех до первого
  назначения; удаление проекта снимает привязку, а не удаляет данные.
