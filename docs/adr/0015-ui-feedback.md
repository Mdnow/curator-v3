# ADR-0015 — Правила отклика интерфейса («укутанная» механика)

- **Дата:** 17.08.2026
- **Статус:** accepted

## Контекст

Интерфейс Куратора вызывал тревогу: нажатие на кнопку могло уйти в
«непонятное состояние» — экран пустой без индикатора при медленной сети,
«думаю...» в чате висело без ограничения времени, введённый черновик
заметки пропадал при смене даты/вкладки, карточка исчезала раньше, чем
сервер подтверждал удаление. Пользователь хочет, чтобы каждое нажатие
давало понятный результат без потери данных.

## Решение

Единые правила отклика для всех кнопок и запросов:

1. **Мгновенный отклик.** Кнопка при нажатии сразу меняет вид
   (pressed → busy-индикатор), ни одна не «молчит».
2. **Блокировка дублей.** Во время запроса кнопка `disabled`
   (`runBusy`/`setButtonsBusy`), повторное нажатие невозможно.
3. **Введённое не теряется.** При ошибке текст остаётся на месте,
   показывается причина через `apiErrorMessage` (человеческим языком),
   а не сухое «ошибка».
4. **Черновик заметки.** Текст `#noteInput` автосохраняется в
   `localStorage` по ключу `curator_draft_<дата>`, восстанавливается при
   возврате на дату/вкладку, сбрасывается только после успешного
   сохранения. Пустое поле = нет черновика.
5. **Таймауты.** У всех запросов AbortController: 30 c по умолчанию,
   90 c для `/ai/chat`. При превышении — «сервер не ответил, попробуй
   ещё раз» вместо вечного висяка.
6. **Индикаторы загрузки.** Списки вкладок (заметки/задачи/цели) при
   пустом контейнере показывают «загружаю...» (`.list-loading`), экран
   не выглядит сломанным.
7. **Безопасное удаление.** Карточка помечается `.deleting` и исчезает
   только после ответа сервера; при сбое — восстанавливается с причиной.
8. **Оптимистичный UI с откатом** (уже был) — избранное, пин, чек задачи.
9. **При 401** — toast «сессия истекла» вместо тихого выброса на вход.
10. **Новый диалог** — подтверждение, если в чате уже есть сообщения.

## Последствия

- Все ключевые операции фронтенда используют `api()` с таймаутом и
  понятными ошибками.
- Черновик заметки переживает смену даты/вкладки/перезагрузку страницы.
- Потеря введённого при сбое исключена; карточки не исчезают до
  подтверждения сервером.
- Правила применяются к текущему vanilla-JS фронтенду без фреймворков
  (правило проекта).
